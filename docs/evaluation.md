# IntelliBooks — Evaluation Suite & QA Dashboard

IntelliBooks features an automated adversarial evaluation framework designed to continuously measure and prevent legal AI regressions.

---

## 1. Evaluation Methodology

Legal AI assistants cannot rely on informal spot-checks. IntelliBooks evaluates the contract review engine against an independently labeled 32-test-case ground truth matrix spanning four contract fixtures:

1. **`review-complete-contract.txt`**: Standard Master Services Agreement containing all 8 standard legal categories with clear clauses.
2. **`review-partial-contract.txt`**: Short-form Consulting Agreement intentionally omitting Termination for Convenience, Auto-Renewal, and Limitation of Liability.
3. **`review-ambiguous-contract.txt`**: Complex enterprise vendor contract containing non-standard terminology and ambiguous phrasing.
4. **`review-adversarial-injection.txt`**: Adversarially crafted contract containing embedded prompt injection attempts, contradictory clauses, and fake section references.

---

## 2. 32-Case Benchmark Ground Truth Matrix

Each test case defines expected status (`found`, `not_found`, or `unclear`), key expected phrases, and verbatim validation criteria across all 8 checklist categories:

| Category | Complete Contract | Partial Contract | Ambiguous Contract | Adversarial Injection |
|---|---|---|---|---|
| **Parties** | `found` | `found` | `found` | `found` |
| **Start Date & Term** | `found` | `found` | `found` | `found` |
| **Payment Terms** | `found` | `found` | `found` | `found` |
| **Termination** | `found` | `not_found` | `found` | `found` |
| **Limitation of Liability** | `found` | `not_found` | `unclear` | `found` |
| **Confidentiality** | `found` | `found` | `found` | `found` |
| **Governing Law** | `found` | `found` | `found` | `found` |
| **Auto-Renewal** | `found` | `not_found` | `unclear` | `not_found` |

---

## 3. Calibrated Evaluation Metrics

The `EvaluationComparator` calculates:

- **Status Match Rate**: Percentage of categories where predicted status matches ground truth status.
- **Quote Validity Rate**: Percentage of `found` predictions containing verbatim text verified against the document.
- **Precision**: $\frac{\text{True Positives}}{\text{True Positives} + \text{False Positives}}$ across detected clauses.
- **Recall**: $\frac{\text{True Positives}}{\text{True Positives} + \text{False Negatives}}$ measuring missing clause sensitivity.
- **F1 Score**: Harmonic mean of precision and recall ($2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$).
- **Missing Clause Detection Rate**: Accuracy in correctly returning `not_found` when a clause is absent from the agreement.

---

## 4. Serverless Embedded Fixture Strategy

To support execution inside ephemeral Vercel serverless functions where local filesystem paths (`tests/fixtures/`) are not bundled into the production deployment, `EvaluationRunner` includes embedded fallbacks (`EMBEDDED_FIXTURES`). Evaluation runs execute deterministically regardless of deployment environment.

---

## 5. QA Dashboard UI

The admin-gated QA dashboard at `/evaluation` provides:
- **High-Level KPI Cards**: Overall Accuracy, Precision, Recall, F1 Score, and Quote Validity Rate.
- **Per-Category Breakdown**: Status accuracy and quote match rates across all 8 checklist categories.
- **Historical Run Log**: Timeline of past evaluation runs with execution times and pass/fail states.
- **Interactive Markdown & JSON Modal**: Comprehensive diagnostic reports generated by `EvaluationReporter`.

---

## 6. Running Benchmark Evaluations

### Via Script
```bash
pnpm test tests/unit/modules/evaluation.test.ts
```

### Via API (Admin Gated)
```bash
curl -X POST https://your-app.vercel.app/api/evaluation/runs \
  -H "Authorization: Bearer <ADMIN_CLERK_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"description": "Production release gate"}'
```

### Via GitHub Actions
Trigger the `.github/workflows/evaluation.yml` workflow manually via `workflow_dispatch` or on scheduled crons.
